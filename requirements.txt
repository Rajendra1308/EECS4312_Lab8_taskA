## 1. Problem Understanding - Describe the problem your system solves.
System purpose:The objectivbe of the system is to recommend appointment time slots in the user given window of working hours where a potential meeting can be scheduled, ensuring they do not clash with the user-given busy hours/intervals.The system must behave deterministically and also resolve scheduling conflicts automatically without the user intervening. It should throw explicit errors instead of handling edge cases silently. Lastly, it should support the users who trust the system decisions and the ones  who rely on explainable outputs.


Inputs to the system:

 start time: str -- format = ("00:00" - "23:59")
 end time: str -- format =  ("00:00" - "23:59")
 busy interval: list[tuple(str)] --- format = [(start_time_i, end_time_i), (start_time_j, end_time_j] 
buffer time: int (any integer which will correspond to minutes between 2 meetings)
 meeting duration: int (same format as above - it will translate to minutes per meeting)
 candidate time window: list[tuple(str)]  -- format =  [(candidate_start_time, candidate_end_time)] this is an optional parameter
number of slots (N): int 

## 2. Assumptions - List assumptions about the environment, users, or inputs.
A1:
It is assumed that the times are for a single day and not more than that
A2:
It is assumed that the times provided are in 24 hour format containing only hours and minutes
A3:
It is assumed that the buffer time is consistent across all the meetings/ same buffer time applies after every meeting
A4:
It is assumed that the meeting duration is same for all meetings
A5:
It is assumed that the working window is not always the normal working hours from 09:00-17:00
A6:
It is assumed that the system can automatically make decisions to resolve scheduling conflicts

## 3. Functional Requirements - Describe the main behaviors the systemmust perform.
FR1:
The system shall raise a distinct error when startTime is larger than or equal to endTime
FR2:
The system shall raise a distinct error when duration is less than or equal to zero
FR3:
The system shall raise a distinct error when N is less than or equal to zero
FR4:
The system shall return an empty list when no bookable slot can be scheduled


## 4. System Constraints - Constraints are conditions the system must
always respect. Each constraint should reference the persona attribute
it originates from.
C1: The system shall resolve scheduling conflicts automatically
Derived from persona attribute: Jane (expects automatically handling conflicts)


C2: The system shall not produce different outputs for identical inputs over simultaneous calls
Derived from persona attribute: Jane (Systems behave inconsistently in similar situations.)



C3: The system shall not spam the user with too many notifications, including failures/conflicts resolved/ and duplicate slots generated
Derived from persona attribute: Jane (Having to manually resolve conflicts or check system correctness.)

C4: The system must gracefully hadle errors with describing the error messages 
Derived from persona attribute: Mo (Not understanding why the system changed or rejected an action.)

C5: The system shall log the justifications for resolving conflicts/not being able to generate slots
Derived from persona attribute: Mo (Silent failures or dropped reminders/requests.)

C6: The system shall have a consistent response for any boundary scenario
Derived from persona attribute: Mo (Inconsistent responses across repeated or boundary scenarios.)
